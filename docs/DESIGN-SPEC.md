# ClaudeDeck 界面规格

> 这份文档是给 **Claude Design** 读的输入。它描述「要画什么」,不描述「怎么实现」。
> 功能层已经跑通(见 `README.md`),所以下面每一个状态都是真实存在、必须有画面的状态。

---

## 0. 产品一句话

ClaudeDeck 是一个 Windows 桌面应用,把命令行工具 Claude Code 变成图形界面的聊天软件。
用户在窗口里跟 Claude Code 对话、随时切换模型、并在左侧列表中回到任何一次历史会话。

**设计语言**:沿用 Organic。
**目标气质**:像一个安静的写作工具,不像一个开发者控制台。用户在这里说话,不在这里看日志。

---

## 2. 屏幕清单

应用共 **4 个屏幕**,按启动时的判定顺序排列。前两个是一次性的,用户配置完就再也看不到。

```
启动
 └─ 环境检查中 ────────────────► 屏幕 A:加载
     ├─ 未装 Claude Code ─────► 屏幕 B:首次配置
     ├─ 已装、未选工作目录 ───► 屏幕 C:选择工作目录
     └─ 都就绪 ───────────────► 屏幕 D:主界面(聊天)
```

---

### 屏幕 A — 加载

出现时间通常小于 1 秒,但**必须有画面**,否则冷启动会闪一下白屏。

- 居中,一行字:`正在检查运行环境…`
- 需要一个品牌感的静止或轻微动效元素(不要转圈 spinner,太工具化)

---

### 屏幕 B — 首次配置

**这是新用户看到的第一屏,决定他能不能顺利用起来。**

单卡片,居中,最大宽度约 560px。卡片内两个分区 + 一个主按钮。

**分区 1:Claude Code 命令行**

两种状态,只会出现一种:

- **未检测到**(默认走到这屏就是这个状态)
  - 说明文案:`未检测到 claude 命令。ClaudeDeck 通过官方 Agent SDK 驱动 Claude Code,必须先安装它。`
  - 一段可复制的命令:`npm install -g @anthropic-ai/claude-code`
  - 主按钮:`一键安装`
  - 安装中:按钮变为 `安装中…` 且禁用,下方出现一个可滚动的日志区(等宽字体,最高约 140px)
  - 安装失败:日志区内出现错误文本,需要一个明确的失败视觉
- **已检测到**
  - 一行成功态:`已检测到:<版本号>`

**分区 2:凭据(可选)**

- 说明文案:`留空则沿用你在终端里已登录的 Claude Code 账号。填写后将覆盖,API Key 由系统凭据加密保存。`
- 输入框 1:`ANTHROPIC_BASE_URL(如使用中转端点)`
- 输入框 2:`API Key`,密码型(圆点遮蔽)
- **需要设计一个「已加密保存」的信任提示**——这是这一屏的加分点,让用户知道 key 没有明文躺在硬盘上

**底部**:主按钮 `保存并继续`

---

### 屏幕 C — 选择工作目录

- 标题:`选择工作目录`
- 说明:`Claude Code 的会话按目录归属。选定目录后,这里会列出该目录下的全部历史会话。`
- 主按钮:`选择目录…`(唤起系统文件夹选择框)
- **最近使用**列表:0 到 10 条,每条是一个完整路径。路径很长,需要设计截断规则(建议保留盘符和末两级)
  - 空态:整个「最近使用」区块不出现

---

### 屏幕 D — 主界面

三段式布局:**左侧栏 264px + 右侧主区自适应**。

```
┌──────────────┬────────────────────────────────────┐
│ + 新建会话    │  模型▾   Effort ●●○○○   权限▾  [停止] │ ← 工具栏
├──────────────┼────────────────────────────────────┤
│ 会话列表      │                                    │
│ (可滚动)      │  对话区(可滚动)                    │
│              │                                    │
├──────────────┼────────────────────────────────────┤
│ 工作目录      │  [输入框                    ] [发送] │
│ [切换目录]    │                                    │
└──────────────┴────────────────────────────────────┘
```

#### D1. 左侧栏

**顶部**:整宽主按钮 `+ 新建会话`

**中部:会话列表**(功能 3 的主体)
每条包含:
- 标题(单行,溢出省略号)
- 时间(次要色,如 `2026/7/27 15:32`)
- 可选:Git 分支名

状态:
- 普通
- 悬停
- **当前选中**(必须和悬停明确区分,这是演示录屏里要被看见的)
- 空态:`该目录下还没有会话。`

> 设计需要决定:是否按「今天 / 昨天 / 更早」分组?列表可能有上百条。

**底部**:当前工作目录路径(小字、次要色、可换行)+ 整宽 `切换目录` 按钮

#### D2. 工具栏

从左到右三个控件,**这是功能 2 的主体,要显眼但不喧宾夺主**:

1. **模型**——下拉选择
   - 选项由程序在运行时向 SDK 查询,**不是写死的**。当前机器实测返回 5 项,
     文案就是下面这些(设计时按 4–8 项预留):

     | 显示名 | 说明 |
     |---|---|
     | Default (recommended) | 默认项,已由 SDK 提供,不需要界面另造 |
     | Opus (1M context) | 长上下文变体,名字里带括号,较长 |
     | Fable | |
     | Sonnet | |
     | Haiku | |

   - 注意最长的一项是 `Default (recommended)`,版式要容得下
2. **Effort(努力程度)**——**5 格分段控件**,不是滑块,也不是下拉
   - 五档固定为:`low` `medium` `high` `xhigh` `max`
   - 需要设计:选中态、未选中态、以及五格连成一体的视觉
   - 建议配一句悬停解释,普通用户不知道 effort 是什么
3. **权限**——下拉选择,四项:
   | 值 | 文案 | 悬停解释 |
   |---|---|---|
   | default | 询问 | 每次写入或执行前请求批准 |
   | acceptEdits | 自动接受编辑 | 文件编辑免批准,命令仍需批准 |
   | plan | 计划模式 | 只读分析,不做任何改动 |
   | bypassPermissions | 完全放行 | 不再询问,谨慎使用 |
   - `完全放行` 需要一个警示性的视觉区别

**右端**:`停止` 按钮,**仅在 Claude 正在输出时出现**

#### D3. 对话区

两种气泡:

- **用户消息**:有描边或底色的块,右侧留白,最大宽度约 780px
- **Claude 消息**:无气泡,直接排版正文;顶部一行小字署名 `Claude`
- 正文保留换行,行高宽松(1.6 以上)

**流式输出态**:Claude 的回复是逐字出现的。需要设计一个「正在输出」的指示(光标、呼吸点,或其他),它会持续数秒到数十秒,**不能烦人**。

**工具调用提示**:Claude 有时会读写文件。需要一个轻量的行内提示,形如「正在使用工具:Read」,视觉权重低于正文。

**权限请求卡片**(功能之外但已实现,是加分项):
- 出现在对话流末尾,不是弹窗
- 文案:`Claude 请求使用工具:<工具名>`
- 两个按钮:`允许`(主要)/ `拒绝`
- 需要明确的「等待你决定」的视觉张力,因为在用户点击之前,整个对话是停住的

**错误态**:一行醒目但不惊悚的错误文本。

**空态**(新建会话后):需要设计。建议放品牌元素 + 一两句引导,而不是纯白。

#### D4. 输入区

- 多行文本域,自动增高(约 46px 起,最高 180px)
- 占位文案:`给 Claude Code 发消息…(Enter 发送,Shift+Enter 换行)`
- 右侧 `发送` 主按钮,内容为空或正在输出时禁用

## 3. 组件清单

设计系统里需要覆盖的原子:

| 组件 | 用在哪 | 需要的状态 |
|---|---|---|
| 主按钮 | 全局 | 默认 / 悬停 / 按下 / 禁用 / 加载中 |
| 次按钮 | 全局 | 默认 / 悬停 / 按下 / 禁用 |
| 下拉选择 | 模型、权限 | 默认 / 展开 / 禁用 |
| 分段控件(5 格) | Effort | 每格的选中 / 未选中 / 悬停 |
| 文本输入 | 配置屏 | 默认 / 聚焦 / 密码型 |
| 多行输入 | 输入区 | 默认 / 聚焦 / 增高后 |
| 列表项 | 会话列表、最近目录 | 默认 / 悬停 / 选中 |
| 卡片 | 配置屏、权限请求 | 普通 / 警示 |
| 日志区 | 安装过程 | 等宽、可滚动 |
| 消息气泡 | 对话区 | 用户 / Claude / 流式中 |

## 4. 设计时需要知道的约束

这些是功能层已经定死的,画稿时不要绕开:

1. **模型列表是动态的**,数量和名字由运行时决定,不能把某个具体型号画进版式里当装饰。
2. **Effort 恰好 5 档**,不多不少。
3. **权限恰好 4 档**(SDK 底层还有两档,产品上不暴露)。
4. **会话按工作目录分桶**。切换目录 = 整个左侧列表换一批。
5. **切模型和切权限是瞬时的**,不打断对话;**切 Effort 会短暂重连**,需要一个几百毫秒的过渡态,不能让界面看起来卡死了。
6. 一次只有一个会话是「活的」。点击列表切换会话时,前一个会话会被关闭。

## 5. 留给设计的开放问题

推稿时需要拿主意的:

- 会话列表要不要按时间分组?上百条时怎么办?
- 「正在输出」的指示用什么形态才能持续几十秒而不烦人?
- 权限请求卡片如何做到「醒目但不像报错」?
- 新建会话的空态放什么?
- Effort 这个概念怎么用一句中文让非开发者看懂?
- 深色主题做不做?
